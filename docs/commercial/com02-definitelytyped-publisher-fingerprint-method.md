## Implemented discovery

The existing immutable-name/version registry manifest collector now records `candidateTypesPublisherContentHash` only when the raw npm registry version manifest includes a canonical **64-character lowercase SHA-256**. It also records `candidateTypesPublisherHashStatus` as `EXACT_VERSION_PUBLISHER_HASH_CANDIDATE`, `NOT_ADVERTISED` or `INVALID_PUBLISHER_HASH_CANDIDATE`; non-`@types` records have `NOT_DEFINITELYTYPED`. The existing registry `dist.integrity` must still match frozen Yarn SHA-512 before the 26-version triage can use any candidate; no untrusted hash counts as a signed release record.

The same-run `build-definitelytyped-triage.mjs` report now includes the candidate fingerprint and counts how many of the exact 26 npm versions advertise it. Its `historicalGitSourceContentMatches` remains **zero** until exact source revisions and historical publisher algorithms can be independently reproduced. Missing/malformed hash values are explicitly not promoted. All 26 records remain `immutableSourceCommit:null`, `sourceContentHashIndependentlyMatched:false`, `npmPublisherToSourceIndependentlyVerified:false`. No source/asset rights or license is automatically inferred.
