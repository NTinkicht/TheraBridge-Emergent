## Security decisions

- Invitation tokens: 32 random bytes, stored as SHA-256 only, single use, 7-day expiry, rotated on every resend (old links stop working), sent only in a URL fragment (`/invite#token=…`) and in POST bodies, so they never reach server access logs. API responses and audit/center events never contain them.
- Delivery is restricted: local dev mailbox (local + loopback only) and/or a server-side outbox directory (`DEV_OUTBOX_DIR`, mode 0600 files, never served over HTTP, refused at boot outside synthetic environments). No real email is sent.
- Public invitation endpoints: pre-auth CSRF, 30 requests per network per 15 minutes, strong password policy on activation.
- CENTER_ADMIN is granted only by platform invitation. Center administrators manage only COORDINATOR, THERAPIST and CLINICAL_SUPERVISOR; they cannot change their own access, and the last active administrator cannot be removed (serialised with a row lock on the center).
- Clinical capabilities remain DENY for every role. No billing or plans are introduced.
